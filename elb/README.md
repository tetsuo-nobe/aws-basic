# ELB (Application Load Balancer) ハンズオン

AWS の Application Load Balancer (ALB) を使って、2つの EC2 インスタンスへ負荷を分散する構成を作成するハンズオンです。

最初に CloudFormation でネットワークと EC2 インスタンスをまとめて作成し、その後マネジメントコンソールでターゲットグループと ALB を作成します。最終的に ALB の DNS 名でアクセスすると、リクエストが 2つのインスタンスに振り分けられ、表示される AZ 名が交互に変わることを確認します。

## このハンズオンで作成する構成

```
                    Internet
                       |
                  [ ALB (Public) ]  ← ALB-SG (0.0.0.0/0 から HTTP 許可)
                    /          \
        [ Public Subnet 1 ]  [ Public Subnet 2 ]
                    |              |
        [ Private Subnet 1 ]  [ Private Subnet 2 ]
        [   EC2 (Web-1)    ]  [   EC2 (Web-2)    ]  ← Web-SG (ALB-SG から HTTP 許可)
                    \              /
                   [ NAT Gateway (Public Subnet 1) ]
                       |
                    Internet (アウトバウンドのみ)
```

CloudFormation で作成するリソース:

- VPC（1つ）
- Public サブネット（2つ / 2つの AZ）
- Private サブネット（2つ / 2つの AZ）
- NAT ゲートウェイ（1つ）
- EC2 インスタンス（2つ / Private サブネットに 1つずつ配置）
  - ユーザーデータで Apache HTTP Server をインストールし、`Hello from (AZ 名)` を表示する index.html を作成
- セキュリティグループ 2つ
  - **Web-SG**: EC2 インスタンス用。ALB-SG からの HTTP のみ許可
  - **ALB-SG**: ALB 用。`0.0.0.0/0` からの HTTP を許可

コンソールで手動作成するリソース:

- ターゲットグループ（2つのインスタンスをターゲットに指定）
- Application Load Balancer (ALB)

---

## サインイン

1. ご自身に割り当てられた **2桁の番号** を確認して下さい。
2. AWS アカウントにアクセス: [こちら](https://d-9567586b55.awsapps.com/start) を右クリックしてブラウザの新しいタブで開きます。
3. ユーザー名とパスワード、使用する許可セットはインストラクターから案内します。
4. 東京リージョン（ap-northeast-1）を使用します。

---

## 1. CloudFormation でスタックを作成する

CloudShell を使って、CloudFormation テンプレートからスタックを作成します。

### 1-1. CloudShell を開く

1. AWS マネジメントコンソールにサインインする
1. ページ上部で、東京リージョン（**アジアパシフィック（東京）**）が選択されていることを確認する
1. 画面上部のナビゲーションバーにある **CloudShell アイコン**（`>_` のようなアイコン）をクリックする
1. ターミナルが起動するまで待つ（初回は少し時間がかかります）

### 1-2. テンプレートを取得する

1. CloudShell のターミナルに、以下のコマンドを貼り付けて実行する
    - テンプレートファイルをダウンロードします。

```bash
curl -o alb_handson_template.yaml https://raw.githubusercontent.com/tetsuo-nobe/aws-basic/main/elb/alb_handson_template.yaml
```

2. ファイルが取得できたことを確認する

```bash
head alb_handson_template.yaml
```

> `AWSTemplateFormatVersion: '2010-09-09'` から始まる内容が表示されれば成功です。

### 1-3. スタックを作成する

1. まず、自分の番号を環境変数 `MYID` に設定する
    - **`99` の部分を、ご自分の番号に置き換えてください。**

```bash
MYID=99
```

2. 続いて、以下のコマンドを貼り付けて実行し、スタックを作成する
    - 上で設定した `MYID` がスタック名に使われます。

```bash
aws cloudformation deploy \
  --stack-name alb-handson-stack-${MYID} \
  --template-file alb_handson_template.yaml \
  --capabilities CAPABILITY_IAM \
  --region ap-northeast-1
```

3. `Waiting for stack create/update to complete` と表示され、しばらく待つ（5〜7 分程度）
4. `Successfully created/updated stack - alb-handson-stack-99` のように表示されれば作成完了です。

> IAM ロールを作成するため `--capabilities CAPABILITY_IAM` が必要です。

### 1-4. 作成されたリソースを確認する

1. 上部の検索バーに `ec2` と入力し、**EC2** サービスを選択する
1. 左メニューの **「インスタンス」** をクリックする
1. `alb-handson-web-1` と `alb-handson-web-2` の 2つのインスタンスが起動していることを確認する
1. **「ステータスチェック」** が合格になるまで待つ

> インスタンスは Private サブネットにあるため、パブリック IP は割り当てられていません。インターネットからは ALB 経由でのみアクセスします。

---

## 2. ターゲットグループを作成する

ALB がリクエストを転送する先となるターゲットグループを作成し、2つの EC2 インスタンスを登録します。

### 2-1. ターゲットグループの作成画面を開く

1. EC2 コンソールの左メニューを下にスクロールし、**「ロードバランシング」** の下にある **「ターゲットグループ」** をクリックする
1. **「ターゲットグループの作成」** ボタンをクリックする

### 2-2. 基本設定

以下の項目を設定します。

| 項目 | 設定値 |
|------|--------|
| **ターゲットタイプの選択** | `インスタンス` |
| **ターゲットグループ名** | `alb-handson-tg-(番号)`（例：`alb-handson-tg-99`） |
| **プロトコル : ポート** | `HTTP : 80` |
| **VPC** | `alb-handson-vpc` を選択する |
| **プロトコルバージョン** | `HTTP1` のまま |

### 2-3. ヘルスチェック

1. **「ヘルスチェックパス」** は `/` のままにする
1. その他の項目はデフォルトのままにする
1. **「次へ」** ボタンをクリックする

### 2-4. ターゲットの登録

1. **「使用可能なインスタンス」** の一覧で、`alb-handson-web-1` と `alb-handson-web-2` の **両方にチェック**を入れる
1. **「保留中として以下を含める」** ボタンをクリックする
1. 下部の **「ターゲットを確認」** に 2つのインスタンスが表示されることを確認する
1. **「ターゲットグループの作成」** ボタンをクリックする

---

## 3. Application Load Balancer (ALB) を作成する

### 3-1. ロードバランサーの作成画面を開く

1. EC2 コンソールの左メニューで **「ロードバランサー」** をクリックする
1. **「ロードバランサーの作成」** ボタンをクリックする
1. **「Application Load Balancer」** の **「作成」** ボタンをクリックする

### 3-2. 基本設定

以下の項目を設定します。

| 項目 | 設定値 |
|------|--------|
| **ロードバランサー名** | `alb-handson-(番号)`（例：`alb-handson-99`） |
| **スキーム** | `インターネット向け` |
| **IP アドレスタイプ** | `IPv4` |

### 3-3. ネットワークマッピング

1. **「VPC」** で `alb-handson-vpc` を選択する
1. **「マッピング」** で **2つのアベイラビリティーゾーン**にチェックを入れる
1. 各 AZ の **サブネット**で、`alb-handson-public-subnet-1` と `alb-handson-public-subnet-2`（**Public サブネット**）をそれぞれ選択する

> ALB は Public サブネットに配置します。Private サブネットは選択しないでください。

### 3-4. セキュリティグループ

1. **「セキュリティグループ」** で、デフォルトのセキュリティグループが選択されている場合は **「X」** で外す
1. `ALB-SG` を選択する

### 3-5. リスナーとルーティング

1. **「リスナー」** が `HTTP : 80` になっていることを確認する
1. **「デフォルトアクション」** の転送先で、手順 2 で作成した `alb-handson-tg-(番号)` を選択する

### 3-6. 作成の実行

1. 設定内容を確認し、**「ロードバランサーの作成」** ボタンをクリックする
1. **「ロードバランサーを表示」** をクリックする
1. 作成した ALB を選択し、**「状態」** が `アクティブ` になるまで待つ（数分程度）

---

## 4. 動作確認（負荷分散の確認）

### 4-1. ターゲットが healthy になったことを確認する

1. EC2 コンソールの左メニューで **「ターゲットグループ」** をクリックする
1. `alb-handson-tg-(番号)` を選択する
1. **「ターゲット」** タブで、2つのインスタンスの **「ヘルスステータス」** が `healthy` になるまで待つ

> `unhealthy` や `initial` の場合は、ヘルスチェックが完了するまで少し待ってから再読み込みしてください。

### 4-2. ALB の DNS 名を確認する

1. 左メニューで **「ロードバランサー」** をクリックする
1. 作成した ALB を選択する
1. **「説明」** タブ（または詳細ペイン）の **「DNS 名」** をコピーする

> DNS 名の形式：`alb-handson-99-xxxxxxxxx.ap-northeast-1.elb.amazonaws.com`

### 4-3. ブラウザからアクセスする

1. ブラウザの新しいタブを開く
1. `http://<コピーした DNS 名>` にアクセスする
1. **「Hello from ap-northeast-1a」** のように AZ 名が表示されることを確認する
1. **ページを何度か再読み込み**する
1. **表示される AZ 名が交互に変わる**ことを確認する（例：`ap-northeast-1a` ⇄ `ap-northeast-1c`）

> ALB はデフォルトでラウンドロビンに近い形でリクエストを 2つのインスタンスに振り分けます。各インスタンスは自身が属する AZ 名を表示するため、再読み込みするたびに表示される AZ が入れ替わり、負荷分散が行われていることを確認できます。

> ブラウザがキャッシュを表示して AZ 名が変わらない場合は、スーパーリロード（Ctrl + F5）を試すか、少し間隔をあけて再読み込みしてください。

## 5. クリーンアップ

ハンズオン終了後、不要な課金を防ぐためにリソースを削除します。**CloudFormation で作成していないリソース（ALB・ターゲットグループ）を先に削除してから、スタックを削除します。**

### 5-1. ALB を削除する

1. EC2 コンソールの **「ロードバランサー」** で、作成した ALB を選択する
1. **「アクション」** から **「ロードバランサーの削除」** を選択する
1. 確認欄に `confirm` と入力し、**「削除」** をクリックする

### 5-2. ターゲットグループを削除する

1. EC2 コンソールの **「ターゲットグループ」** で、作成したターゲットグループを選択する
1. **「アクション」** から **「削除」** を選択して削除する

### 5-3. CloudFormation スタックを削除する

1. CloudShell に戻り、自分の番号を環境変数 `MYID` に設定する
    - 手順 1-3 と同じ CloudShell セッションを使っている場合は、すでに設定済みのため省略できます。
    - **`99` の部分を、ご自分の番号に置き換えてください。**

```bash
MYID=99
```

2. 以下のコマンドを実行してスタックを削除する

```bash
aws cloudformation delete-stack \
  --stack-name alb-handson-stack-${MYID} \
  --region ap-northeast-1
```

3. 削除の完了を待つ場合は、以下のコマンドを実行する

```bash
aws cloudformation wait stack-delete-complete \
  --stack-name alb-handson-stack-${MYID} \
  --region ap-northeast-1
```

> スタックを削除すると、VPC・サブネット・NAT ゲートウェイ・EC2 インスタンス・セキュリティグループ・IAM ロールがまとめて削除されます。NAT ゲートウェイと Elastic IP は課金対象のため、削除の完了を必ず確認してください。

## まとめ

このハンズオンで学んだことを振り返りましょう。

| 学んだこと | 内容 |
|-----------|------|
| CloudFormation | テンプレートからネットワークと EC2 をまとめて構築 |
| CloudShell | ブラウザ上のシェルから AWS CLI でスタックを作成 |
| Public / Private サブネット | ALB は Public、EC2 は Private に配置する構成 |
| NAT ゲートウェイ | Private サブネットからのアウトバウンド通信を実現 |
| セキュリティグループ連携 | ALB-SG からの通信のみ Web-SG で許可する多層防御 |
| ターゲットグループ | ALB の転送先となるインスタンスのグループ化 |
| Application Load Balancer | 複数インスタンスへの負荷分散（AZ 名が交互に変化） |
