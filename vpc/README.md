# VPC 作成ハンズオン

AWS マネジメントコンソールを使用して VPC を作成し、Public サブネット内に Web サーバー（EC2 インスタンス）を構築するまでの手順です。

VPC 作成ウィザードの **「VPC など」** を利用して、VPC・サブネット・ルートテーブル・インターネットゲートウェイなどをまとめて作成します。

## このハンズオンで作成する構成

- VPC（1つ）
- Public サブネット（2つ）
- Private サブネット（なし）
- Public サブネットへの Public IP 自動割り当て設定
- セキュリティグループ（HTTP を全許可するインバウンドルール）
- Public サブネット上の EC2 インスタンス（ユーザーデータで Apache HTTP Server をインストール）

---

## サインイン

1. ご自身に割り当てられた **2桁の番号** を確認して下さい。
2. AWS アカウントにアクセス: [こちら](https://d-9567586b55.awsapps.com/start) を右クリックしてブラウザの新しいタブで開きます。
3. ユーザー名とパスワード、使用する許可セットはインストラクターから案内します。
4. 東京リージョンを使用します。

---

## 1. VPC の作成（「VPC など」でまとめて作成）

VPC 作成ウィザードの **「VPC など」** を使うと、VPC・サブネット・ルートテーブル・インターネットゲートウェイをまとめて自動作成できます。

### 1-1. VPC ダッシュボードを開く

1. AWS マネジメントコンソールにサインインする
1. ページ上部で、東京リージョンを選択する
    - **「アジアパシフィック（東京）」** と表示されていれば OK
1. 上部の検索バーに `vpc` と入力し、**VPC** サービスを選択する
1. **「VPC を作成」** ボタンをクリックする

### 1-2. 「VPC など」を選択する

1. **「作成するリソース」** で **「VPC など」** を選択する
    - VPC、サブネット、ルートテーブル、インターネットゲートウェイがまとめて作成されます。

### 1-3. VPC の設定

以下の項目を設定します。**(番号) の部分は、ご自分の番号に置き換えてください。**

| 項目 | 設定値 |
|------|--------|
| **名前タグの自動生成** | チェックを入れ、`my-vpc-(番号)` を入力（例：`my-vpc-99`） |
| **IPv4 CIDR ブロック** | デフォルトのまま（例：`10.0.0.0/16`） |
| **IPv6 CIDR ブロック** | 「IPv6 CIDR ブロックなし」のまま |
| **テナンシー** | デフォルトのまま |

### 1-4. サブネットの設定

Public サブネットを 2つ、Private サブネットを 0（なし）にします。

| 項目 | 設定値 |
|------|--------|
| **アベイラビリティーゾーン (AZ) の数** | `2` |
| **パブリックサブネットの数** | `2` |
| **プライベートサブネットの数** | `0` |

> **プライベートサブネットの数を必ず `0` に設定してください。** これにより Private サブネットは作成されません。

### 1-5. その他の設定

1. **「NAT ゲートウェイ」** は **「なし」** のままにする
    - Private サブネットがないため、NAT ゲートウェイは不要です。
1. **「VPC エンドポイント」** は **「なし」** を選択する
1. **「DNS オプション」** はデフォルト（DNS ホスト名を有効化、DNS 解決を有効化）のままにする

### 1-6. 作成の実行

1. 右側の **「プレビュー」** で、VPC と 2つの Public サブネットが作成される構成になっていることを確認する
1. **「VPC を作成」** ボタンをクリックする
1. 作成が完了したら **「VPC を表示」** をクリックする

## 2. Public サブネットに Public IP を自動割り当てする設定

「VPC など」で作成した場合でも、Public サブネットのパブリック IP 自動割り当ては有効になりません。以下の手順で手動で有効化します。**2つの Public サブネットそれぞれに対して**実施してください。

### 2-1. サブネットの設定を開く

1. VPC コンソールの左メニューで **「サブネット」** をクリックする
1. 作成された Public サブネット（名前に `public` を含むもの）を 1つ選択する

### 2-2. 自動割り当て IP 設定を有効化する

1. **「アクション」** ドロップダウンから **「サブネットの設定を編集」** を選択する
1. **「パブリック IPv4 アドレスの自動割り当てを有効化」** にチェックを入れる
1. **「保存」** をクリックする
1. もう 1つの Public サブネットに対しても、2-1 から同じ手順を繰り返す

> この設定により、Public サブネットに起動した EC2 インスタンスへ自動的にパブリック IP が割り当てられ、インターネットからアクセスできるようになります。

## 3. セキュリティグループの作成

Web サーバー用のセキュリティグループを作成します。

### 3-1. セキュリティグループの作成画面を開く

1. VPC コンソールの左メニューで **「セキュリティグループ」** をクリックする
1. **「セキュリティグループを作成」** ボタンをクリックする

### 3-2. 基本設定

以下の項目を設定します。**(番号) の部分は、ご自分の番号に置き換えてください。**

| 項目 | 設定値 |
|------|--------|
| **セキュリティグループ名** | `my-web-sg-(番号)`（例：`my-web-sg-99`） |
| **説明** | `Allow HTTP from anywhere` など任意 |
| **VPC** | 手順 1 で作成した `my-vpc-(番号)` を選択する |

### 3-3. インバウンドルール

1. **「インバウンド」** で **「ルールを追加」** をクリックする
1. 以下のルールを設定する

| 項目 | 設定値 |
|------|--------|
| **タイプ** | `HTTP` |
| **プロトコル** | `TCP`（自動設定） |
| **ポート範囲** | `80`（自動設定） |
| **ソース** | `カスタム` で `0.0.0.0/0` を入力（Anywhere-IPv4 を選択でも可） |

> HTTP（ポート 80）を全世界（`0.0.0.0/0`）からのアクセスを許可します。

### 3-4. アウトバウンドルール

1. アウトバウンドルールはデフォルトのままにする
    - デフォルトで **「すべてのトラフィック」** が `0.0.0.0/0` 宛に許可されています。

### 3-5. 作成の実行

1. **「セキュリティグループを作成」** ボタンをクリックする

## 4. Public サブネットに EC2 インスタンスを作成する

作成した VPC の Public サブネットに、Apache HTTP Server が動作する EC2 インスタンスを起動します。

### 4-1. EC2 の起動画面を開く

1. 上部の検索バーに `ec2` と入力し、**EC2** サービスを選択する
1. 左メニューで 「インスタンス」の下にある **「インスタンス」** をクリックする
1. **「インスタンスを起動」** ボタンをクリックする

### 4-2. 名前とタグ

1. **「名前」** に下記のインスタンス名を入力する
    - **(番号) のところは、ご自分の番号に置き換えてください。**
    - ```
      my-web-instance-(番号)
      ```

### 4-3. AMI の選択

1. **「Amazon マシンイメージ (AMI)」** はデフォルトの「Amazon Linux 2023 AMI」のままにする
1. アーキテクチャは「64 ビット (x86)」のままにする

### 4-4. インスタンスタイプの選択

1. **「インスタンスタイプ」** のドロップダウンから `t3.micro` を選択する

### 4-5. キーペア（ログイン）

1. **「キーペア名」** のドロップダウンから **「キーペアなしで続行」** を選択する

### 4-6. ネットワーク設定

1. ネットワーク設定の **「編集」** をクリックする
1. 以下の項目を設定する

| 項目 | 設定値 |
|------|--------|
| **VPC** | 手順 1 で作成した `my-vpc-(番号)` を選択する |
| **サブネット** | 手順 1 で作成した Public サブネットのいずれか 1つを選択する |
| **パブリック IP の自動割り当て** | **「有効化」** になっていることを確認する |
| **ファイアウォール (セキュリティグループ)** | **「既存のセキュリティグループを選択する」** を選択する |
| **共通のセキュリティグループ** | 手順 3 で作成した `my-web-sg-(番号)` を選択する |

### 4-7. ユーザーデータの設定

1. **「高度な詳細」** セクションを展開する
1. 一番下の **「ユーザーデータ」** の入力欄に、以下のスクリプトを貼り付ける

```bash
#!/bin/bash
dnf install -y httpd
systemctl enable httpd
systemctl start httpd
echo "<h1>Hello from Public Subnet</h1>" > /var/www/html/index.html
```

> ユーザーデータはインスタンスの初回起動時に実行されます。ここでは Apache HTTP Server（httpd）をインストールして起動し、`Hello from Public Subnet` と表示する index.html を作成しています。

### 4-8. インスタンスの起動

1. ページ右下の **「インスタンスを起動」** ボタンをクリックする
1. **「すべてのインスタンスを表示」** をクリックする
1. **「ステータスチェック」** が「3/3 のチェックに合格しました」になるまで待つ（3〜4 分程度）

---

## 5. ブラウザからアクセスする

### 5-1. パブリック IP アドレスを確認する

1. EC2 ダッシュボードの「インスタンス」画面で、作成したインスタンスを選択する
1. 下部の詳細ペインで **「パブリック IPv4 アドレス」** を確認する

### 5-2. ブラウザでアクセスする

1. ブラウザの新しいタブを開く
1. `http://<パブリック IPv4 アドレス>` にアクセスする
1. **「Hello from Public Subnet」** と表示されれば成功です。

> ユーザーデータの実行完了まで、インスタンス起動後さらに 1〜2 分ほどかかる場合があります。表示されない場合は少し待ってから再度アクセスしてください。

> http プロトコルでのアクセスが制限されている環境では表示できない場合があります。

---

## 6. セキュリティグループによるアクセス制御の確認

セキュリティグループのインバウンドルールを変更すると、Web ページへのアクセスがどう変わるかを確認します。HTTP の許可を外すとアクセスできなくなり、元に戻すと再びアクセスできることを体験します。

### 6-1. インバウンドルールを削除してアクセスできないことを確認する

1. VPC コンソール（または EC2 コンソール）の左メニューで **「セキュリティグループ」** をクリックする
1. 手順 3 で作成した `my-web-sg-(番号)` を選択する
1. **「インバウンドルール」** タブをクリックし、**「インバウンドのルールを編集」** をクリックする
1. HTTP（ポート 80）のルールの右側にある **「削除」** をクリックする
1. **「ルールを保存」** をクリックする

### 6-2. Web ページにアクセスできないことを確認する

1. ブラウザで手順 5 と同じ `http://<パブリック IPv4 アドレス>` に再度アクセスする
    - すでに開いているタブがある場合は、ページを再読み込みする
1. **ページが表示されず、タイムアウトする**ことを確認する

> HTTP のインバウンドルールを削除したことで、`0.0.0.0/0` からのポート 80 へのアクセスが拒否され、Web ページにアクセスできなくなります。セキュリティグループはインバウンドを許可制で制御しており、許可がなければ通信は届きません。

### 6-3. インバウンドルールを元に戻してアクセスできることを確認する

1. 再び `my-web-sg-(番号)` の **「インバウンドルール」** タブで **「インバウンドのルールを編集」** をクリックする
1. **「ルールを追加」** をクリックし、以下のルールを設定する

| 項目 | 設定値 |
|------|--------|
| **タイプ** | `HTTP` |
| **ソース** | `カスタム` で `0.0.0.0/0` を入力（Anywhere-IPv4 を選択でも可） |

1. **「ルールを保存」** をクリックする
1. ブラウザで再度 `http://<パブリック IPv4 アドレス>` にアクセスし、**「Hello from Public Subnet」** が再び表示されることを確認する

> セキュリティグループの変更は即時に反映されます。ルールを元に戻すことで、再びインターネットから Web ページにアクセスできるようになります。

## 7. クリーンアップ

ハンズオン終了後、不要な課金を防ぐためにリソースを削除します。**作成した順序と逆の順序で削除します。**

### 7-1. EC2 インスタンスを終了する

1. EC2 ダッシュボードの **「インスタンス」** 画面で、作成したインスタンスを選択する
1. **「インスタンスの状態」** ドロップダウンから **「インスタンスを終了 (削除)」** を選択する
1. 確認ダイアログで **「終了 (削除)」** をクリックする
1. インスタンスの状態が **「終了済み」** になるまで待つ

### 7-2. セキュリティグループを削除する

1. VPC コンソールの左メニューで **「セキュリティグループ」** をクリックする
1. 作成した `my-web-sg-(番号)` を選択する
1. **「アクション」** から **「セキュリティグループを削除」** を選択して削除する

> インスタンスが完全に終了する前はセキュリティグループを削除できない場合があります。その場合は少し待ってから再度実行してください。

### 7-3. VPC を削除する

1. VPC コンソールの左メニューで **「お使いの VPC」** をクリックする
1. 作成した `my-vpc-(番号)` を選択する
1. **「アクション」** から **「VPC の削除」** を選択する
1. 確認欄に `削除` と入力し、**「削除」** をクリックする

> VPC を削除すると、関連するサブネット・ルートテーブル・インターネットゲートウェイもまとめて削除されます。

## まとめ

このハンズオンで学んだことを振り返りましょう。

| 学んだこと | 内容 |


|-----------|------|
| VPC 作成ウィザード | 「VPC など」で関連リソースをまとめて自動作成 |
| Public サブネット | インターネットに接続できるサブネットを 2つ作成 |
| Public IP 自動割り当て | Public サブネットのインスタンスへ自動的にパブリック IP を付与 |
| セキュリティグループ | HTTP を全許可するインバウンドルールの設定 |
